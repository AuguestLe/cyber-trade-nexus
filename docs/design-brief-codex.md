# 任务：为 NEXUS 全球交易态势大屏产出高保真设计图（纯静态 HTML）

你是资深视觉设计师 + 前端工程师。请先读取 `docs/PRD.md`，产出 5 张 1920×1080 的设计图（高保真静态 HTML，可直接截图交付）。

## 交付目录与文件（只允许写这些文件）

- `docs/design/dashboard.html` — 首页大屏（态势总览）
- `docs/design/map.html` — 全球交易地图页（含右侧交易详情抽屉展开态）
- `docs/design/login.html` — 登录页
- `docs/design/trades.html` — 交易明细页（含筛选栏 + 表格 + 详情抽屉展开态）
- `docs/design/admin.html` — 管理员控制台（用户 / Mock 数据 / 系统设置三栏）
- `docs/design/design-system.md` — 色板、字号、间距、切角、发光、动效的设计 token 说明

禁止修改 `docs/PRD.md`；禁止创建其他目录或文件；禁止 npm install；禁止联网下载图片/字体/CDN。

## 硬性约束

1. 每个 HTML 单文件自包含：内联 CSS（可内联少量 SVG），不引用任何外部 URL、字体、图片、JS 库。
2. 画布固定 1920×1080：`html,body{width:1920px;height:1080px;overflow:hidden}`，单屏无滚动条。按 PRD 7.4 的设计基准。
3. 与 PRD 完全一致的色板（深底 `#05070D/#0A0F1C/#101A2E`、青 `#00F0FF`、品红 `#FF2BD6`、紫 `#7B5CFF`、琥珀 `#FFB547`、红 `#FF4D6D`、绿 `#39FF9E`、文字 `#E6F5FF/#8AA3C0/#4B6480`）。涨=红、跌=绿（中国区规范）。
4. 中文字体用系统无衬线栈；数字用 `ui-monospace, "JetBrains Mono", "SF Mono", Menlo, Consolas, monospace`，等宽对齐；标题大写英文 HUD 风格。
5. 视觉必须"赛博指挥中枢"而非后台报表：八边切角卡片、1px 霓虹描边、四角准星、扫描线、细网格背景、发光数字、HUD 编号标签（如 `D-01 / KPI`）、低亮度噪点/CRT 微光。每个页面都要有明确的层次与视觉焦点，避免均匀铺满导致糊成一片。
6. 首页布局严格按 PRD 4.1：顶部栏 64px；三栏 22% / 50% / 28%；底部行情带 56px。全部 10 个模块 D-01~D-10 都要出现（KPI×6、分时成交额主图、简化世界地图、实时流水、告警流、资产占比、地区排行、买卖盘深度、系统雷达、滚动行情带）。
7. 地图页：暗色世界底图 + 20~30 个发光节点 + 多条弧形空中连线（带流动粒子视觉）+ 左侧筛选 / 图层控制 + 顶部工具栏（搜索、播放/暂停、倍速、播放时间轴、实时/全部切换）+ 右侧已展开的交易详情抽屉。视觉上弧线要能看出方向（卖方→买方），用青/品红/琥珀三色区分资产类别，异常线红色。
8. 交易明细页：筛选栏 + 虚拟滚动表格（时间/交易ID/卖方/买方/资产/方向/金额/价格/状态/延迟/风险分）+ 行选中态 + 右侧详情抽屉；状态色标（filled 绿 / pending 琥珀 / failed 红 / flagged 品红）。
9. 控制台：三栏分区（用户列表、Mock 数据控制台、系统设置），需要开关、滑杆、按钮、表格的真实控件样貌；体现权限提示。
10. 登录页：账号密码、图形验证码、记住我、显示密码、演示账号一键填充、DEMO 声明；视觉要有品牌感（NEXUS 标识、网格、光晕、两侧装饰性数据柱）。
11. 所有页面都要有 `DEMO / 模拟数据` 标识、右上角身份徽章、顶部导航（登录页除外，登录页不需要导航）。
12. 数据文案要真实可信：如 24H 成交额 `$48.62B`、成功率 `99.93%`、平均延迟 `38ms`、风险指数 `27.4`；交易对名如 `BTC/USD`、`600519.SH`、`EUR/USD`、`XAU/USD`；节点名如 上海、香港（中国香港）、新加坡、东京、伦敦、法兰克福、纽约、芝加哥、迪拜、悉尼、圣保罗、孟买。
13. 设计要可直接落地：避免无法实现的极细节纹理依赖；动效只做视觉暗示（可用 CSS 动画静态预览），不用外部库。
14. 页面尺寸 1920×1080 由浏览器截图验证，请自觉保证内容不溢出、不重叠、无留白空洞。每张图至少包含 3 个明确可交互控件（选择态/悬停态可静态画出）。

## 设计要求

- 视觉统一：以 `dashboard.html` 为母版，其他页面复用同一套 token、导航、卡片、按钮、表格、抽屉语言。
- 信息密度高但可读：KPI 数字突出，次要信息降亮度；用分组、间距、发光强度做层次。
- 拒绝 AI 味的紫色渐变堆砌、圆角白卡、居中大标题；要硬朗、切角、精密仪器感。
- 世界地图用简化但可辨识的大陆轮廓 SVG path（自绘，不要求地理精确），不要用占位矩形或随机散点；先保证"看起来像地球"。
- 输出前自检：每个 HTML 用 `python3` 或 `node` 简单检查标签闭合？不需要，但结构必须完整可打开。

完成后用 `-o` 输出一份简短的设计说明（每个页面的视觉决策、交互控件清单）。不要跑任何服务或截图。
